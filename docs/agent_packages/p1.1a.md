## 2. 交付物

### 2.1 共享 1D 执行器

新建 `src/npps/npps_arithmetic_operations/npps_elementwise_executor.h`，提供本包及后续 NPPS 包可复用的 1D 元素级执行器：

- `DTypePolicy<T>` / traits：整数饱和（8u/8s/16u/16s/32u/32s/64u/64s）、浮点直通、复数按实部/虚部分量、`Npp16f`。
- 二元 kernel 模板：`out[i] = op(a[i], b[i])`，支持：
  - 普通二元（两个输入 + 一个输出）；
  - 带 `nScaleFactor` 的整数缩放版本（NPP 的整数结果缩放语义）；
  - 原地 `_I` 版本（`pSrcDst` 同时作为输出）；
  - 混合输入/输出类型（如 `16s32f`、`16s32s`、`32s64f` 等，以 CSV 中的签名为准）；
  - 单线程/多线程无关的确定性计算。
- 参数校验：空指针、负长度、零长度的 `NppStatus` 必须与 NPP 13.4 对齐（用差分测试确认，不要凭文档猜测）。
- kernel launch：
  - 1D，256 threads/block；
  - **launch 前调用 `cudaGetLastError()` 清空陈旧错误**（MACA 运行时会残留 `invalid argument`），launch 后检查；
  - 失败返回 `NPP_CUDA_KERNEL_EXECUTION_ERROR`。
- 所有实现走 `nppStreamCtx.hStream`；非 `_Ctx` 入口由生成器统一转发到 `_Ctx`。

> 说明：`nppsDiv_Round` 带 `NppRoundMode`，请把 round mode 作为策略传入 kernel；`nppsAddProduct` 是 `pDst = pDst + pSrc1*pSrc2` 的累加语义，不要把 `pDst` 当成纯输出覆盖（以 NPP 差分结果为准）。

### 2.2 生成 wrapper

为每个 family 写一个 spec（或一个包含 `call_by_family` 的 spec），放在 `mpp_scripts/families/`，然后运行：

```bash
python3 tools/npp_api_catalog.py --group nppsAdd --list      # 确认清单
python3 mpp_scripts/gen_family.py --spec mpp_scripts/families/<spec>.json          # dry run
python3 mpp_scripts/gen_family.py --spec mpp_scripts/families/<spec>.json --emit    # 生成
```

- 生成文件放在 `src/npps/npps_arithmetic_operations/`，文件名 `<family>_generated.cpp`。
- 不允许手改生成文件；改 spec/executor 后重新生成。
- 如果单文件过大，可以按 family 拆分，但要保持 spec 与源文件一一对应。

### 2.3 差分测试

新建 `test/unit/diff/test_npps_binary_generated.cpp`（文件名必须匹配 `diff/test_*_generated.cpp`）。要求：

- 覆盖本包 **所有有代表性的签名形状**：至少每种 dtype × {普通, Sfs, 原地, 混合输出} × {Ctx, 非 Ctx} 各一条；若某形状只有一个函数，则该函数必须被覆盖。
- 每个 case 使用 `npp_diff::Case`：
  - case id 稳定：`nppsBinary/<family>/<variant>/<case>`；
  - 输入用 `make_uniform<T>(n, seed)` 或按 dtype 的边界值构造；
  - 输出用 `device_output(..., ValueKind::<kind>, rtol, atol)`；
  - 整数输出必须精确比较；浮点容差 ≤ 1e-5（按需收紧/放宽，并在注释中说明）。
- 长度至少覆盖 `{1, 17, 257, 1024}`；缩放因子覆盖 `{0, 1, 4, 8}`（按 dtype 有效范围）；原地 case 必须验证输入缓冲区被正确更新。
- 额外 contract case：空指针（返回 `NPP_NULL_POINTER_ERROR`）、`nLength == 0`、负长度；以 5090 的 record 结果为准。
- 所有 case 在 `build-nvidia`（5090）上 record 通过，再在本地 MPP verify 通过。
