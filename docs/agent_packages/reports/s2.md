## 2. nppiCircularRadialProfile_32f_C1R_Ctx（已完成）

### 2.1 逆推出的算法（5090 实测，非文档）

用“单像素冲激 + 全图扫描”探针（33x33 逐像素注入 1.0，读回 24 个 `NppiProfileData`）得到每个像素归属哪个环，
再用 7 组配置（小数/整数/负中心、33x33 与 40x25、S=12/16/24/48）拟合，得到 **100% 复现**的规则：

* **ring 0**：与 `oCenter` 距离 **< 1 像素**的所有像素（整数中心 1 个；半像素中心 4 个；
  例如中心 (31.75,0.25) 只有 3 个，因为 (31,1) 距离 1.0607 > 1 —— 这条是唯一不能用
  “floor/ceil 四个角”解释的点，必须先做冲激测量才能发现）。
* **ring k (1 ≤ k < nProfileSamples)**：半径为 k 的**数字化圆周**。对每一 ROI 行 y（`|y-cy| ≤ k`）：
  `v = sqrt(k² - (y-cy)²)`，取 `x = floor(cx-v)` 与 `x = ceil(cx+v)` 两个像素（越界丢弃，左右重合只记一次）。
  由于只在圆周上采样，绝大多数内部像素**不属于任何环**（33x33/24 环只覆盖 679/1089 个像素），
  所以环形数据是稀疏的，nPixels 只统计被采到的像素。
* **半径不按 ROI 归一化**：覆盖半径 `0..nProfileSamples-1`，更远的像素直接忽略
  （S=12 的 33x33 剖面 total=268，S=48 时 24..47 环全 0）。
* `nMeanIntensity` = 被采样像素算术平均；`nStdDevIntensity` = **总体**标准差（`sqrt(E[x²]-mean²)`，
  棋盘图 0/1 实测 sd=0.5 精确）；空环输出 `{0, 0, 0}`。
* 状态契约（fork 隔离逐案测量）：`pSrc/pProfileData == nullptr → NPP_NULL_POINTER_ERROR`；
  `oSizeROI.width/height < 0 → NPP_SIZE_ERROR`；任一维为 0 → `NPP_NO_ERROR`（空操作）；
  `nProfileSamples == 0` → `NPP_NO_ERROR`；**不校验 nSrcStep**（0/负/奇数/过小都返回 OK）；
  中心在 ROI 外、超大 (±1e6)、NaN 都返回 OK（NaN 中心不写任何像素）。

## 3. 未完成项与原因

### 3.1 nppiEllipticalRadialProfile_32f_C1R_Ctx（1 个函数）

已完成的部分（可用于下一次续跑）：

* **距离度量已确定**：先按 `nOrientationRadians` 旋转 `(dx,dy)` 得 `(u,v)`，再取
  `t = sqrt(u² + (v/ratio)²)`（ratio=2 时把 y 方向“压缩”2 倍）。用该度量做 per-pixel `floor(t)`
  分类，与 5090 冲激图**全部 1065 个被赋环像素零冲突**（rot90：1041/1041；rot45 有 18 个受
  π/4 打印精度影响）。
* **但 NPP 不是 per-pixel 分类**：33x33/ratio=2 只覆盖 1065/1089 个像素，缺口恰好是**每个环的“顶盖”**：
  `(16,15),(17,15) / (16,13),(17,13) / … / (15,1)…(18,1)`（中心上方每隔一行的中心像素），
  下方完全正常 —— 说明实现是“逐环按行光栅化”，且顶部的行循环有 off-by-one。
  试过的 4 种“缩放空间逐行光栅化”模型最好只命中 773/1065（其余模型 372–763），
  无法在本次时间内定死；再试下去需要 graph-capture 看 kernel 序列（`tools/5090_probes_s2/wgraph.cu` 已有 WMSSSIM 版本可改写）。
* **ratio 契约（实测）**：`0.5 / 0 / -2 / 1e-6 → NPP_RANGE_ERROR(-7)`；`1.0 / 2.0 / NaN → OK`；
  `orientation=NaN → OK`；其余契约与 circular 相同（null→-8，负 ROI→-6，空 ROI/空 samples→OK，不校验 step）。
  即 ratio 有下限但 **> 1 的收敛值未测**（下次应补 0.51、0.75、1e5 等）。

### 3.2 nppiMSSSIM_8u_C1R(+_Ctx)（2 个函数）

* **ROI 下限已定**：`width >= 176 && height >= 176`（11·2⁴），否则 `NPP_SIZE_ERROR(-6)`；
  非方阵 `176x128 / 128x176 / 200x160` 全部 -6，`176x176` OK。`step < width` 时是 `-16 STEP_ERROR`。
  WMSSSIM 无此限制（最小 16x16）。
* **MSSSIM ≠ 经典 MS-SSIM 乘积**（WMSSSIM 才是经典式：我们现有实现的逐级
  `mean(cs^w)`(0..3)·`mean((l·cs)^w)`(4) 与 NPP WMSSSIM 在平滑纹理上吻合到 1e-5）。
  实测差异（纹理 `a=(7x+13y+5)&0xff`、`b=a+1`；噪声为 LCG 随机对）：

  | 尺寸/纹理 | SSIM | **MSSSIM** | WMSSSIM |
  |---|---:|---:|---:|
  | 176 平滑 | 0.974529 | 0.994815 | 0.994452 |
  | 256 平滑 | 0.974538 | 0.994870 | 0.994754 |
  | 320 平滑 | 0.974480 | 0.994873 | 0.995054 |
  | 176 噪声 | 0.155834 | **0.018854** | 0.245594 |
  | 256 噪声 | 0.154225 | **0.010583** | 0.241252 |
  | 176 常数 100/110 | 0.995451 | **0（精确 0）** | 0.999370 |
  | 176 相同图 | 1 | 1 | 1 |

  常数图 → 0 说明 MSSSIM 不是“逐级 `cs^w` 连乘 + 末级 `l`”那类公式（那类对常数图会给出
  `l^w = 0.99518^0.1333 ≈ 0.9994`）；噪声图上 MSSSIM 又远低于任何权重排列下的经典乘积
  （本地 float64 复算经典式 176 噪声 = 0.1693/0.2730，均不在 0.0189 附近）。
  下一步必须用 graph capture（`tools/5090_probes_s2/wgraph.cu` 改成 176x176 的 MSSSIM）
  看它到底跑了几级、是否复用 WMSSSIM 的 Gaussian 通道。
