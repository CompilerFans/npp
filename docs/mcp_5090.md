# 5090 远程执行 MCP（用户级）

`tools/mcp_5090_server.py` 是一个无第三方依赖的 stdio MCP server，把
`metax@10.2.120.6`（RTX 5090 D v2 / CUDA 13.4）上的常用操作暴露为 MCP 工具，
供交互会话和 headless 子 agent 使用。

## 安装（当前用户全局）

```bash
tools/install_mcp_5090.sh
```

脚本会：

1. 把 server 安装到 `~/.local/share/mcpp-5090/mcp_5090_server.py`（稳定路径，
   不依赖某个 worktree）；
2. 写 `~/.config/mcpp-5090-mcp.json`（headless agent 用 `--mcp-config` 加载）；
3. 执行 `claude mcp add -s user ...`，注册到用户级配置；
4. 打印 `claude mcp list` 健康状态。

凭据仍在 `~/.config/mcpp-5090.env`（`SSHPASS`、`MCPP_5090_HOST`、
`MCPP_5090_DIR`），不会写入仓库。

## 工具

| 工具 | 作用 |
|---|---|
| `sync` | rsync 当前 checkout 到远端（排除 build/.git/artifacts） |
| `build` | 在远端 configure + build `build-nvidia`（NVIDIA NPP） |
| `test` | 运行远端 gtest target（默认 `diff_tests`） |
| `record` | 以 `NPP_RECORD_DIR` 运行 `diff_tests` 录制 golden |
| `pull` | 把远端记录拉回本地 `artifacts/5090/npp_records` |
| `status` | GPU/CPU/磁盘状态 |
| `run` | 任意远端 shell 命令（逃生口） |

所有工具支持 `remote_dir`；并行 agent 必须传各自独立的目录（例如
`~/mcMPP-ref-<id>`），避免构建/录制互相覆盖。`run_package.sh` 会为每个包导出
`MCPP_5090_DIR=~/mcMPP-<pkg>`，MCP server 与 `tools/remote5090.sh` 都遵循它。

## Headless 子 agent

```bash
claude -p --bare \
  --mcp-config "$HOME/.config/mcpp-5090-mcp.json" --strict-mcp-config \
  --permission-mode bypassPermissions \
  --allowedTools "Bash Read Write Edit Glob Grep mcp__mcpp-5090__sync mcp__mcpp-5090__build mcp__mcpp-5090__test mcp__mcpp-5090__record mcp__mcpp-5090__pull mcp__mcpp-5090__status mcp__mcpp-5090__run" \
  "用 mcp__mcpp-5090__status（target=summary）确认 5090 可用。"
```

`status` 的 `target` 是必填枚举 `summary`：公司 DSV4 在“零参数工具调用”时会
生成非法 JSON（`{}""`），必填参数可强制合法输入。其它工具本身都有参数。

## 已验证

- `claude mcp list` → `mcpp-5090 ... ✔ Connected`
- headless DSV4 调用 `mcp__mcpp-5090__status` → 返回
  `NVIDIA GeForce RTX 5090 D v2`
- 直接 stdio 协议测试：initialize / tools/list / tools/call 均通过
