# Family specs for `gen_family.py`

A family spec describes the mechanical part of an API family: which catalog
functions belong to it and how each variant calls the hand-written executor.
Kernels, validation, workspace handling and differential tests remain
hand-written.

## Schema

| Field | Required | Meaning |
|---|---|---|
| `family` | yes | Family name used in reports (`nppsSum`). |
| `module` | yes | Header module from `api_analysis/api_catalog.csv`. |
| `source` | yes | Generated `.cpp` path, relative to the repo root. |
| `includes` | no | Extra headers the generated file includes (executor header first). |
| `families` | no | Catalog families to select; defaults to `[family]`. |
| `functions` | no | Exact function names to select (overrides `families`). |
| `exclude` | no | Exact names to skip (hand-written exceptions). |
| `call` | yes | Default executor call expression for `_Ctx` wrappers. |
| `call_by_family` | no | Per-family call template, checked before `call_variants`. |
| `call_variants` | no | Ordered list of `{contains, call}`; the first whose `contains` string appears in the parameter list wins. |
| `ctx_only` | no | Reserved; non-Ctx adapters are generated by default when the twin exists. |

Placeholders available in call templates:

- `{name}` — full function name (`nppsSum_16s_Sfs_Ctx`)
- `{family}` — spec family (`nppsSum`)
- `{dtype}` — C type for the first dtype token (`Npp16s`, `Npp32fc`, …)
- `{channels}` — parsed channel count (nppi only)
- `{layout}` — `packed`, `planar`, `ac4`, `masked` (nppi only)

The call expression must use the parameter names from the public signature
verbatim. The generator validates that `nppStreamCtx` exists if the template
mentions it, and emits `(void)nppStreamCtx;` otherwise.

## Example: mixed scaled/unscaled variants

```json
{
  "family": "nppsSum",
  "module": "npps_statistics_functions.h",
  "source": "src/npps/npps_statistics_functions/npps_sum_generated.cpp",
  "includes": ["npps_sum_executor.h"],
  "families": ["nppsSum", "nppsSumGetBufferSize"],
  "call_by_family": {
    "nppsSumGetBufferSize": "nppi::statistics::nppsSumGetBufferSize<{dtype}>(nLength, hpBufferSize)"
  },
  "call_variants": [
    {"contains": "16s32s", "call": "nppi::statistics::nppsSumMixed<Npp16s, Npp32s>(...)"},
    {"contains": "nScaleFactor", "call": "nppi::statistics::nppsSumSfs<{dtype}>(pSrc, nLength, pSum, nScaleFactor, pDeviceBuffer, nppStreamCtx.hStream)"}
  ],
  "call": "nppi::statistics::nppsSum<{dtype}>(pSrc, nLength, pSum, pDeviceBuffer, nppStreamCtx.hStream)"
}
```

`call_variants` are evaluated in order, so put the more specific mixed-type
variants before the generic `nScaleFactor` rule.

## Workflow

```bash
# Inspect the selection and statuses
python3 mpp_scripts/gen_family.py --spec mpp_scripts/families/npps_sum.json --list

# Dry run
python3 mpp_scripts/gen_family.py --spec mpp_scripts/families/npps_sum.json

# Write the generated wrappers
python3 mpp_scripts/gen_family.py --spec mpp_scripts/families/npps_sum.json --emit

# If the family replaces stubs in src/nppi/nppi_not_support.cpp
python3 mpp_scripts/gen_family.py --spec ... --emit --prune-stubs
```

Rules:

1. Never edit a generated file by hand; change the spec (or the executor) and
   regenerate.
2. Real implementations are skipped automatically. `--force` is only for
   regenerating a family you own.
3. Generated wrappers are C ABI because they are defined after `npp.h`
   declarations; do not wrap them in `extern "C"` yourself.
4. Non-Ctx wrappers acquire the managed stream with `nppGetStreamContext()` and
   return its status on failure.
5. One commit per family: spec + generated file + executor + tests.
